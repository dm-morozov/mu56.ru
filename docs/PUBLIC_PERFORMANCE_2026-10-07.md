# Скорость публичного сайта — 7 октября 2026

Проверены https://mu56.ru/, /characters и /packages. PageSpeed Insights API
ответил HTTP 429, поэтому результаты ниже получены официальным Lighthouse CLI
в отдельном headless Chrome на компьютере владельца, а не сервисом Google.
Проверки не отправляли заявки и не меняли сайт.

Условия: mobile, экран 412×823 CSS px, simulated throttling, RTT 150 мс,
пропускная способность 1638 Кбит/с, замедление CPU ×4. Два последовательных
замера на страницу. Первый проверял все четыре категории, второй — performance.
У всех отчётов правильный публичный URL, runtimeError отсутствует.

## Практические выводы

- Во всех шести измерениях performance выше 90. Это результат текущих
  лабораторных проверок; стабильные 90+ на каждом устройстве не обещаются.
  LCP главной и пакетов достигает 3.1 с, поэтому разброс не следует скрывать.
- В первом отчёте пакетов LCP — фотография «Полный Расколбас». Измеренная
  задержка отрисовки около 2.04 с, TTFB около 0.36 с. Фото уже eager/high
  priority. Само скачивание заняло около 0.057 с; дальнейшее сжатие этой
  фотографии не устраняет основную измеренную задержку. В отчёте присутствует
  блокирующая таблица CSS. Для изменения порядка загрузки нужны отдельные
  замеры, а не удаление стилей ради баллов.
- Оценка возможной экономии изображений: каталог около 375 КиБ, пакеты
  около 130 КиБ, главная около 30 КиБ. Это рекомендация аудита, не гарантированное
  улучшение LCP. Уменьшать качество портретов без визуального сравнения не нужно.
- Конкретные замечания доступности: контраст кнопок, пропуск уровня заголовка
  в карточках каталога/пакетов, несовпадение видимого текста и aria-label
  логотипа/ссылок фото пакетов. Их стоит исправлять точечно с визуальной проверкой.
- Полевая статистика CrUX не получена; эти измерения не заменяют реальные
  Core Web Vitals. VPN/маршрут компьютера может влиять на результат.

Полные JSON и HTML лежат локально в .local/public-performance/:
home.report.*, characters.report.*, packages.report.*; повторные JSON
home-2.json, characters-2.json и packages-2.json. Не включать тяжёлые отчёты
в публичную сборку. Один неуспешный запуск повторов с неправильным аргументом
output-path не создал измерений; в таблицу включены только успешные отчёты.

Следующий полезный этап — исправить указанные замечания доступности, затем
измерить изменённые страницы. Повторять всю оптимизацию и менять сервер
на основании этих результатов сейчас не требуется.
