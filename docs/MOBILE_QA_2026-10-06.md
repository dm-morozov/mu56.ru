## Обновление 7 октября: текущая разработка через Wi-Fi

На 3001 теперь запущен Next dev текущего checkout, слушающий 127.0.0.1.
Временный Node TCP-мост `.local/wifi-preview.cjs` слушает только
192.168.0.175:3001 и пересылает подключения на этот dev. Его PID записан в
`.local/wifi-preview.pid`; прежнее ограниченное firewall-правило ActiveStore
остаётся для Node, TCP 3001, локального IP и источников 192.168.0.0/24.
Это текущая рабочая версия с незавершёнными правками, не изолированная
production-сборка ниже. Не вводить реальные заявки для проверки.

Next.js блокировал dev-ресурсы для LAN Origin. В next.config.ts добавлено
чтение NEXT_DEV_ALLOWED_ORIGINS (список hostname через запятую), локально в
игнорируемой frontend/.env.local указан 192.168.0.175. Wildcard не включён;
production-настройки не менялись. После перезапуска по изменению config
форма открылась в Chrome через Wi-Fi URL; добавление азотного шоу обновило
расчёт Бамблби с 6200 до 12600. TypeScript прошёл, отправка заявки не проверялась.
На телефоне требуется обновить страницу после изменения dev-конфигурации.

## Доступ через Wi-Fi

Владелец подтвердил открытие сайта на настоящем телефоне по адресу
`http://192.168.0.175:3001/packages` в общей Wi-Fi сети.

Запущена отдельная production-сборка из `.local/release-qa/clean-checkout`,
Next.js слушает только адрес Wi-Fi `192.168.0.175:3001`. Основные процессы
на 3000 и 8000 сохранены. Тестовый Django слушает `127.0.0.1:8002`,
использует восстановленную базу `mu56_restore_6631682e34df`, уведомления
отключены через `TELEGRAM_ENABLED=false`. Для тестовой версии скопированы
текущие публичные фотографии галерей. Заявки из неё не поступают в рабочую базу.

Проверены HTTP 200 страницы пакетов, доступность фотографии галереи,
`noindex` и CSRF: пустой POST с Wi-Fi Origin и правильным токеном возвращает
400 валидации, не создавая заявку. Полная отправка с телефона пока не проверена.

Сеть Windows имеет профиль Public. Постоянное правило с Profile Any было
отклонено автоматической проверкой. Вместо него создано временное динамическое
правило `mu56 WiFi QA temporary` в `ActiveStore`: только Node.js,
Wireless/Public, TCP 3001, локальный адрес 192.168.0.175, источники
192.168.0.0/24. Правило не записывается в постоянное хранилище.
Профиль самой сети не менялся. Адрес компьютера может измениться при смене сети.

После проверки остановить только тестовые процессы Next.js на 3001 и Django
на 8002 через Ctrl+C в их терминалах. Удаление временного правила:

```powershell
Remove-NetFirewallRule -DisplayName 'mu56 WiFi QA temporary' -PolicyStore ActiveStore
```

Не останавливать рабочие процессы на 3000/8000. Доступ с телефона требует
включённого компьютера и работающих тестовых процессов; это не размещение сайта.

## Первый проход оптимизации — исходные находки

- На новогодней странице постер видео грузится как исходный JPEG примерно
  380 КБ, хотя само видео имеет preload="none" и до запуска не скачивается.
  Подготовить оптимизированный постер, сравнить качество и повторить замеры.
- Проверить шрифты и задержку отрисовки главного изображения; сокращать
  наборы шрифтов только при сохранении всех используемых символов и начертаний.
- Проверить наиболее тяжёлые изображения на остальных страницах. PNG-оригинал
  в репозитории и WebP, реально передаваемый браузеру, измерять отдельно.
- Замечание про размер 2x изображений оценивать с учётом DPR телефона,
  не уменьшать чёткость ради балла. HTTP/2 и поведение HTTPS проверить уже
  на тестовом hosting: локальный HTTP/1.1 не показывает будущие условия.
- На настоящем телефоне проверить меню, поиск героя, маску телефона,
  калькулятор и отправку тестовой заявки. Пока подтверждено открытие сайта.

## Второй проход оптимизации — выполнено

- Постер: создан WebP 1280×720, quality 85 из JPEG 1672×941. Размер
  380532 → 109500 байт (−71.2%). Исходник сохранён. При сравнении превью
  960×540 заметной потери деталей не обнаружено. Видео ссылается на WebP.
- Пять статических начертаний Manrope заменены Fontsource Variable Manrope
  5.3.0 с диапазоном 200–800 и теми же языковыми наборами. Unbounded сохранён.
  Обращений браузера к внешнему сервису шрифтов нет. В новогоднем отчёте
  число загруженных файлов шрифтов 11 → 5, объём 132203 → 89424 байт (−32.4%).
- Главное фото на главной загружается eager с высоким приоритетом.
- Код формы вынесен в отдельный динамический клиентский компонент,
  загружается при первом выборе праздника. Во время загрузки виден статус
  «Открываем форму…». Затем форма остаётся смонтированной и использует
  прежнюю логику выбора/сброса. Объём начального JavaScript на главной
  171545 → 160994 байт, сжатого HTML 35964 → 34101 байт.

Сборка и TypeScript прошли. В браузере проверены главный экран и Новый год
при 360 CSS px, пакеты при 1440 px; переполнения нет. Форма также не имеет
горизонтального переполнения. Первое открытие «Полного Расколбаса» показывает
9400 ₽; после закрытия и выбора «Сладкого вайба» — 5500 ₽. Новогодний тариф
50 минут передаётся в форму: 6000 ₽; азотное шоу увеличивает сумму до 12400 ₽.
