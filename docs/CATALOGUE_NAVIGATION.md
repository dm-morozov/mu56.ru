# Возврат в каталог персонажей

## Поведение

Поиск, категория и порядок героев сохраняются в текущей записи истории браузера.
После открытия карточки браузерная кнопка «Назад» возвращает тот же список и
позицию прокрутки. «Вперёд» снова открывает карточку. Состояния отдельных посещений
каталога не смешиваются: новая навигация на `/characters` начинается с полного
списка и порядка по категориям.

Очистка поиска сохраняет выбранную категорию и порядок. «Сбросить фильтры» и
«Показать всех» очищают поиск и категорию, оставляя выбранный порядок, как и до
этого изменения. Возврат фокуса в поле поиска сохранён.

## Реализация и ограничения

- `catalog-navigation.ts` проверяет небольшой снимок версии 1 под ключом
  `mu56Catalog` в `history.state`. Неизвестные версии не восстанавливаются;
  неизвестные категории, порядок и некорректный поиск заменяются значениями по
  умолчанию. Ввод длиннее 1024 символов продолжает фильтровать, но не сохраняется.
- `replaceState` получает копию существующего состояния со всеми чужими ключами,
  включая внутренние данные Next. Аргумент URL не передаётся. Фильтрация не
  вызывает router-навигацию или запрос данных и не добавляет записи в стек «Назад».
- Текст поиска не добавляется в URL, cookie, localStorage, sessionStorage или
  параметры аналитики. Используется только история этой страницы; управление
  сохранением/восстановлением самой сессии браузера остаётся за браузером.
- Прокрутка записывается после короткой паузы и непосредственно перед обработкой
  ссылки. При возврате она восстанавливается после восстановления списка. Новое
  действие пользователя отменяет ожидающее восстановление. Глобальная настройка
  `history.scrollRestoration` не меняется.
- Начальный HTML и первый hydration-render используют одинаковые значения по
  умолчанию; чтение браузерного состояния выполняется в layout effect. Серверной
  зависимости от `window`, динамических search params и CSR-only fallback нет.
- Поддержаны remount, уже смонтированный каталог при `popstate` и возврат из
  browser back-forward cache (`pageshow.persisted`). Уходящие обработчики и таймеры
  не должны записывать состояние в страницу карточки.
- Если браузер запрещает операции с историей или исчерпал её лимит, поиск и
  фильтры продолжают работать; сохранение в таком окружении не гарантируется.
  Сохранённая позиция также ограничена текущей высотой страницы, если содержимое
  каталога изменилось.

## Проверки

Из корня репозитория:

```sh
node scripts/check_catalog_navigation.mjs
node scripts/check_character_catalog.mjs
npm --prefix frontend run typecheck
```

Первый скрипт проверяет снимки, неизменность framework-метаданных, отсутствие
URL-аргумента, ограничение данных, некорректные состояния и отказ History API.
React/jsdom-проверки дополнительно проверяют настоящий переход по истории с
remount, Back/Forward, независимые посещения, восстановление прокрутки,
очистку/сброс, focus recovery и SSR/hydration без recoverable errors.

Интеграция с фактическим Next router и геометрия проверяются отдельно сценарием
каталога в `scripts/browser-qa/journeys.spec.mjs` на desktop, 390 и 360 px.
Успех React/jsdom сам по себе не подтверждает эту интеграцию или мобильный Safari.

Перед реализацией сверены поставляемые с установленным Next документы:
`01-app/01-getting-started/04-linking-and-navigating.md` (Native History API),
`01-app/03-api-reference/04-functions/use-search-params.md` и
`01-app/01-getting-started/05-server-and-client-components.md`.
