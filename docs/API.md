# API первого релиза

База адресов: `/api/v1/`. Текущая версия — локальная разработка, без публичного запуска. JSON, один домен с будущим фронтендом, CORS не открыт.

| Метод и адрес | Назначение |
| --- | --- |
| `GET offerings/` | Предложения, пагинация по 24. Фильтр `?kind=package`, `show`, `animation`, `transformer`, `extra`, `seasonal` |
| `GET offerings/<slug>/` | Карточка, подтверждённые тарифы, видимые персонажи, этапы пакета |
| `GET characters/` | Видимые персонажи с пагинацией |
| `GET characters/<slug>/` | Описание, отметка доступности и видимые фотографии |
| `GET contacts/` | Проверенные каналы связи. MAX появится после подтверждения ссылки в админке |
| `GET reviews/` | Опубликованные отзывы: имя, текст, источник и ссылка, пагинация по 24 |
| `GET articles/` | Опубликованные статьи с наступившей датой: название, адрес, краткое описание, дата |
| `GET articles/<slug>/` | Полный текст, поисковое описание и видимая связанная программа |
| `GET csrf/` | CSRF-токен и cookie для формы |
| `POST leads/` | Сохранение заявки, HTTP 201 при успехе |

Скрытые карточки по прямому адресу возвращают 404. Каталог допускает только чтение. Цены без подтверждения не отдаются как действующий тариф; внутренние сведения о происхождении цены не входят в ответ.

У персонажей поле `photos` содержит массив `{url, alt, position}`, упорядоченный по `position`, затем ID. Отдаются только фотографии с включённым показом. Без фотографий возвращается `[]`. Ссылки относительные, от корня сайта (`/uploads/...`); внутренний ключ импорта не публикуется. Такие же галереи доступны у персонажей внутри предложения. Загрузка и редактирование выполняются через Django Admin, публичного API загрузки нет.

Редакционные разделы допускают только чтение. Черновики и будущие статьи отсутствуют в списке и по прямому адресу возвращают 404. Статьи сортируются от новых к старым, отзывы — по заданному порядку. Внутренние ключи происхождения отзывов не публикуются.

## Заявка

Обязательны `phone` и `data_consent: true`. Остальные поля необязательны — клиент может обратиться до выбора программы. Российский телефон приводится к `+7…`; поддерживаются записи через 8 и десятизначный мобильный номер.

```json
{
  "name": "Имя клиента",
  "phone": "+7 903 111-22-33",
  "contact_method": "telegram",
  "messenger_handle": "@username",
  "offering": "bumblebee",
  "character": "spider-man",
  "addons": ["silver"],
  "child_age": 6,
  "children_count": 12,
  "location": "Район и площадка",
  "comment": "Пожелания к программе",
  "data_consent": true
}
```

Также доступны `event_date` (`YYYY-MM-DD`), `event_time` (`HH:MM`, время Оренбурга), `second_performer` (только для обычного пакета). `character` в программе трансформера — второй супергерой; сам трансформер выбран через `offering`. Невидимые и недоступные позиции не принимаются, повторные дополнения отклоняются. Совместимость нестандартных комбинаций подтверждает менеджер.

Ответ содержит только случайный номер обращения, статус `received` и сообщение о сохранении. Он не возвращает телефон, заметки или снимок тарифов. Публичного списка и чтения заявок по номеру нет. Клиент не задаёт статус, цены и внутренние поля.

Снимок сохраняет состав и действующие тарифы сервера на момент обращения. Расчёт известных пакетов и шоу после трансформеров выполняется сервером; клиентскую сумму не принимаем. Итог после согласования площадки, дополнительных услуг и дороги подтверждает менеджер. Неизвестный тариф не заменяется нулём или выдуманной ценой.

## Фронтенд формы

Получить токен через `GET /api/v1/csrf/`, затем отправить JSON с cookie и заголовком `X-CSRFToken`. CSRF проверяется и для анонимного пользователя: одной SessionAuthentication в DRF для этого недостаточно. Основа: [Django CSRF](https://docs.djangoproject.com/en/5.2/howto/csrf/), [DRF authentication](https://www.django-rest-framework.org/api-guide/authentication/).

Поле `website` — необязательное скрытое поле-ловушка; посетитель его не заполняет. Ограничение тела JSON — 64 КиБ. Ошибки полей — HTTP 400, отсутствие CSRF — 403, неверный тип тела — 415, частые обращения — 429. На фронтенде сохранять введённые данные при ошибке и блокировать повторное нажатие на время отправки. Успех показывать после ответа 201.

Ограничение 10 обращений в час с IP пока действует в кеше одного процесса. На сервере нужны общий кеш, настройки доверенного прокси и лимиты обратного прокси; не считать текущий механизм полной защитой от атак. Ограничения DRF описаны в [Throttling](https://www.django-rest-framework.org/api-guide/throttling/).

## Обработка

Заявки доступны сотруднику с правами в Django Admin. Статусы: новая, связались, обсуждаем программу, заказ согласован, закрыта без заказа. Заметки менеджера — внутренние. Отдельный этап музыки после программы не включает ведущих.

Получатель уведомлений — Дмитрий в личном чате Telegram. Заявка и задание очереди сохраняются одной транзакцией, telegram_worker отправляет сообщение вне HTTP-запроса. Состояние, ошибки и ручной повтор видны в админке; подключение и живая проверка завершены. Настройка описана в docs/TELEGRAM.md. Версия согласия `draft-v1` — временная, перед запуском нужно подготовить и связать с формой действительный текст и его версию.

В админке есть фильтры «В работе», «Ждут первого контакта», «Завершённые» и состояние Telegram, поиск по контактам/пожеланиям/заметкам. Быстрые действия меняют рабочий статус и сохраняют историю изменений Django. Изменение программы после разговора не переписывает снимок тарифов и не отправляет уведомление повторно.


### Выбор новогоднего тарифа

`POST /api/v1/leads/` принимает необязательный `tariff_code` при сезонной программе: `minutes-30`, `minutes-40`, `minutes-55`, `group-with-sound`. Пустое значение означает помощь в выборе. Код проверяется по подтверждённым тарифам выбранного предложения. Выбранные код, длительность и цена сохраняются в `selection_snapshot.selected_tariff`; снимок не меняется при последующем редактировании каталога. Добавки сохраняются обычным полем `addons`; пока их сезонные цены не подтверждены, общий итог с добавками отсутствует.
