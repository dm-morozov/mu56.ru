## Максимум три полезных следующих проверки/правки

### 1. Уточнить sizes карусели в узком hero — средний приоритет

`frontend/src/components/photo-gallery.tsx`: карусель содержит
sizes="(max-width:700px) 100vw, 1100px".
`frontend/src/app/venues/vinni-puh/venue.module.css`: на экранах >900px
она занимает 1,35/(1,35+1) ширины контейнера за вычетом gap=40px.
При браузерном окне 1280px её фактическая ширина была 658px.
Для этой страницы 1100px завышает размер слота. При 701–900px карусель
полноширинная, однако sizes также остаётся 1100px.

Предлагаемая реализация после согласования: отдельный параметр sizes для
карусели, соответствующий этому hero и брейкпоинту 900px; не менять размеры
lightbox. Проверить выбор кандидата в новом/незакэшированном контексте при
390/768/1280/1440px и DPR 1/2. Сравнить лица и детали костюмов.
Разница 116110 → 79470 байт между вариантами — возможность экономии,
а не подтверждённый выигрыш каждого пользователя: кандидат зависит от DPR
и браузер может повторно использовать ранее загруженный более крупный файл.

### 2. Привести sizes сетки галереи к CSS — средний приоритет

`photo-gallery.tsx`: desktop sizes=400px для grid.
`photo-gallery.css`: две колонки; на /animators и /characters/spider-man
ширина кадра при 1280px составила 581px. На 441–600px сетка остаётся
двухколоночной, но sizes указывает 100vw. Получается недооценка desktop
и переоценка части мобильного диапазона.

Подобрать sizes к одной колонке до 440px и двум выше, учитывая ширину
контейнера и gap. Проверить фото после прокрутки, а не только HTML src.
Это правка соответствия качества/трафика, а не безусловное уменьшение:
на desktop правильный вариант может стать больше для сохранения резкости.

### 3. Проверить приоритет главного изображения героя — низкий приоритет

`frontend/src/app/characters/[slug]/page.tsx`: первый Image не имеет eager,
preload или high priority; публичный DOM /characters/spider-man показывает
loading=lazy. При 1280×720 изображение начинается на y≈485 и видно
в первом экране. После завершения загрузки изображение отображается.

До изменения провести сравнительный мобильный Lighthouse/trace и установить
LCP-элемент. Если именно фото задерживает LCP — дать приоритет только ему.
Не ставить preload всем изображениям персонажей и галерей. В текущем аудите
не доказано, что lazy вызвал ощутимую задержку; это кандидат на эксперимент.

## Локальные исправления после разрешения владельца

Выполнены только первые два пункта:

- PhotoGallery принимает необязательный carouselSizes, прежний default
  сохранён. Страница «Винни-Пуха» передаёт sizes для полноширинной галереи
  до 900px и split hero выше с учётом gap и ограничения контейнера.
- Grid использует sizes="auto, …" при явном loading="lazy": современный
  браузер выбирает источник по реальному месту в раскладке, включая галерею
  внутри статьи. Запасные значения учитывают одну колонку до 440px,
  две колонки выше, gutters контейнера и gap 12/24px.
  В браузере без auto вложенная узкая статья может получить источник больше
  нужного: fallback рассчитан на обычную внешнюю сетку. Визуальная резкость
  при этом не занижается. CSS и размеры lightbox не изменялись.

Правило auto/lazy и fallback сверено с MDN:
https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img#sizes
Перед кодом прочитан раздел sizes установленной документации Next 16.3.7:
frontend/node_modules/next/dist/docs/01-app/03-api-reference/02-components/image.md.
