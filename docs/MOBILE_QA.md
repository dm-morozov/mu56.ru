- Закрытие формы возвращает фокус на «Обсудить эту программу»; Escape закрывает форму.
- Каталог, поиск «Человек-паук»: два результата, включая чёрного Человека-паука. Описание, две галерейные фотографии, переход к форме с выбранным spider-man.

Серверные цены и сохранение проверены 54 backend-тестами на предыдущем этапе. Физическую клавиатуру, автоувеличение iOS, небольшой экран 320 px и полный мобильный заказ до успеха проверить отдельно.

## Дополнение: ошибки и завершение заказа

Проверено 2 октября на production-сборке, фактическая ширина 400 CSS px:
- /animators → форма с animation → выбор spider-man.
- Отправка с пустым телефоном блокируется браузером; фокус на phone.
- При временно остановленном локальном Django CSRF proxy возвращает ошибку: форма сообщает, что отправка не удалась, без технических деталей. Имя, герой, комментарий и согласие сохранены; поля разблокированы, фокус на form-error. POST заявки на этом шаге не выполнялся. Backend восстановлен сразу после проверки.
- После восстановления номер 123 отклонён сервером. Данные остались в форме, заявка не создана.
- С вымышленным +70000000000 и явной пометкой теста форма дошла до успеха; фокус lead-success-title. Диалог успеха clientWidth=scrollWidth=349, форма до успеха 330; горизонтального переполнения нет.
- В БД ровно одна заявка с именем ТЕСТ мобильной формы — не заказ: 5e7ae772-7c9c-4bc1-8ae5-a0efe750d2a2, animation/spider-man. Уведомление sent, attempts=1. Получение владельцем лично в этом проходе не подтверждалось. Тестовая запись оставлена для проверки; звонить и бронировать не нужно.

В коде добавлены таймауты 15 секунд отдельно для CSRF и POST, русские сообщения об ошибке соединения. Для потери подтверждения после POST сообщение предупреждает, что заявка могла сохраниться, и предлагает уточнить по телефону перед повтором. Автоматические повторы POST не добавлены. Таймаут и потеря ответа после POST в браузере не воспроизводились; проверки отказа proxy и серверной валидации не заменяют эти сценарии. Production build и TypeScript прошли.

Скриншот успеха: design/revisions/mobile-order-success.jpg. Физическая клавиатура Android/iOS, 320 CSS px, полный осмотр нижних блоков /animators, ошибки расчёта и блокировка Escape во время длительного запроса остаются для следующего прохода. Viewport сброшен, тестовая вкладка закрыта.

## Завершение проверки таймаутов

Изолированный loopback-прокси scripts/qa_slow_proxy.py на 3011/3012 задерживал CSRF или POST на 22 секунды. Все POST намеренно не передаются Django: эти тесты не создают заявки и уведомления. Тела форм не журналируются. Проверена действующая сборка без тестовых веток в коде приложения.

При фактической ширине 320 CSS px:
- Во время ожидания CSRF поля disabled, Escape оставляет диалог открытым.
- Через 15 секунд сообщение о связи, введённое тестовое имя сохраняется, поля доступны, фокус form-error.
- При задержанном POST через 15 секунд сообщение о возможном сохранении и необходимости уточнить перед повтором; имя сохранено, поля доступны, фокус form-error.
- clientWidth=scrollWidth=250 у диалога в обоих сценариях: горизонтального переполнения нет.
- Снимок: design/revisions/mobile-post-timeout.jpg. Временные прокси остановлены, вкладки закрыты, viewport сброшен. Основные Django/Next не останавливались.

Проверка подтверждает реакцию UI на отсутствие ответа POST; сохранение заявки сервером с последующей потерей ответа не моделировалось. Автоматического повтора нет. Мобильная клавиатура физического телефона и полный визуальный осмотр нижних блоков остаются отдельно; программные сценарии ожидания и ошибок завершены.
