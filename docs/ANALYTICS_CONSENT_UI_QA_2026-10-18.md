# Проверка выбора аналитики — 18 октября 2026

## Изменение интерфейса

При первом показе уведомления доступны две кнопки: «Согласен» и
«Пока без аналитики». Вторая вызывает существующий `choose(false)`:
сохраняет `denied`, останавливает счётчик, удаляет доступные странице
cookies `_ym_*` и скрывает уведомление на прежние 24 часа.

При открытии через «Настройки аналитики» в футере сохранена подпись
«Отключить аналитику». Согласие, ключи localStorage, длительность
скрытия, обработка событий, разрешённые пути и домены не изменены.
Политика и другие юридические тексты не редактировались.

Обе кнопки используют существующие стили бренда и минимальную высоту
44px. Новый CSS-модуль располагает действия рядом с возможностью
переноса; при ширине до 600px текст находится над кнопками. На узкой
раскладке текст кнопок может переноситься. Глобальный CSS не изменён.

## Воспроизводимая проверка

При уже установленных frontend-зависимостях и вспомогательных jsdom /
esbuild в `.local/header-tests`:

```sh
node scripts/check_analytics_consent_ui.mjs
node --experimental-transform-types scripts/check_analytics.mjs
```

Новый скрипт компилирует и монтирует настоящий `SiteAnalytics` с настоящими
`StoreProvider`, reducer и функциями из `analytics.ts`. Заменены только
Next Link и источник pathname. Вспомогательный bundle сохраняется в
игнорируемой `.local/analytics-consent-tests/`; зависимости и lock-файлы
приложения не изменяются.

jsdom работает без загрузки внешних ресурсов и выполнения добавленных
скриптов. Успешная загрузка SDK моделируется DOM-событием `load`;
проверяются вызовы штатной очереди `window.ym`, а не ответы Яндекса.
Таймер и текущее время контролируются тестом.

### Результат: 15 сценариев прошли

1. Первый показ: две подписанные кнопки, ссылка на `/privacy`; до выбора
   нет SDK и событий аналитики.
2. «Пока без аналитики»: `denied`, срок ровно 24 часа, очистка `_ym_*`
   с сохранением других cookies, отсутствие SDK и событий после кликов,
   видео и перехода по страницам.
3. Сохранённый отказ до истечения срока: уведомление скрыто, SDK отсутствует.
4. Истечение срока: уведомление возвращается, отказ не превращается в согласие.
5. Согласие: один SDK-элемент; init, hit и цели появляются только после load.
6. Сохранённое согласие: настройки открываются с прежней подписью;
   отключение останавливает счётчик и события; повторное согласие работает.
7. Настройки после первоначального отказа: можно согласиться, срок скрытия
   и таймер очищаются.
8. Отказ до завершения загрузки SDK: поздний load не запускает аналитику.
9. Отказ из другой вкладки: storage-событие прекращает отслеживание.
10. Открытие формы заявки скрывает уведомление без изменения выбора;
    после закрытия формы оно возвращается.
11. Ошибка записи согласия в localStorage оставляет аналитику выключенной.
12. localhost: уведомление и SDK не появляются.
13. dev.mu56.ru: уведомление и SDK не появляются.
14. `enabled=false`: уведомление и SDK не появляются.
15. Служебный путь `/privacy`: действующее ограничение показа сохранено.

Дополнительно прошли проверки CSS-источника для раскладки и 44px-кнопок,
существующий `check_analytics.mjs` и `git diff --check`.

## Границы проверки

Это проверка поведения React и CSS-источника, не визуальная приёмка.
jsdom не рассчитывает реальные размеры и переносы; высота панели и
отсутствие перекрытия важного контента на 320/360/390/600/768px и при
увеличенном тексте должны быть подтверждены в браузере. Проверка
production-сборки выполняется отдельно для общего набора изменений.

Запросы SDK, реальные события Метрики, заявки, публикация, production
настройки и учётные данные не затрагивались.
