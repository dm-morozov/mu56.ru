# Поисковые описания и имя сайта — 19 октября 2026

## Подтверждённая исходная проблема

Независимый публичный обход после релиза cb17ae5: все 78 адресов sitemap
отвечают HTTP200, имеют уникальные title/description, один self-canonical,
один H1, разрешение индексации и читаемый JSON-LD. Старые адреса героев
перенаправляются на актуальные страницы, несуществующая страница отвечает404.
У всех адресов sitemap найдены входящие внутренние ссылки. Это техническая
доступность, а не доказательство индексации или позиций по каждому запросу.

В части описаний обнаружена механическая обрезка на 180-м символе:
`/packages` заканчивается «оборудо», `/characters/spider-man` — «В ».
В шести описаниях шоу/дополнений исходная точка соединяется с ещё одной
точкой шаблона. На главной есть Organization, но нет WebSite с именем сайта.

## Изменения

- Общий лимит описания сохранён: до180 Unicode-символов. При необходимости
  сокращения выбирается граница слова и ставится многоточие. Короткие
  описания остаются неизменными; пробелы нормализуются. Необычное слово
  длиннее всего лимита сокращается без повреждения Unicode.
- В шаблоне описания услуги завершающая пунктуация исходного текста не
  дублируется. Исходные данные каталога не меняются.
- Для `/packages` и `/characters/spider-man` заданы цельные короткие описания
  из фактического видимого предложения. Вступление пакетов на странице,
  включая оговорку о фоновой музыке, сохранено полностью.
- На главной добавлен единственный WebSite JSON-LD: существующее имя
  «Мир Улыбок», основной URL и стабильный идентификатор. Organization,
  Service, BreadcrumbList, canonical, заголовки, фотографии и тарифы сохранены.
  SearchAction, рейтинги, адрес офиса и новые рекламные обещания не добавлены.

## Почему выбран такой объём

Главная отвечает на «детские праздники Оренбург», `/animators` — на обычную
анимацию, `/characters/spider-man` — на выбор Человека-паука. Эти адреса,
заголовки, коммерческое содержание и внутренние переходы уже существуют.
Новые дублирующие страницы под вариации запросов не требуются.

Google может самостоятельно выбрать текст сниппета; meta description не
гарантирует точного отображения. WebSite сообщает предпочтительное имя,
а не повышает позиции автоматически. Поисковикам нужен повторный обход.

Основания:
- https://developers.google.com/search/docs/appearance/snippet
- https://developers.google.com/search/docs/appearance/site-names
- https://developers.google.com/search/docs/fundamentals/creating-helpful-content

## Проверка

- `node scripts/check_seo.cjs`: существующие canonical/sitemap/цены/безопасный
  JSON-LD плюс Unicode, границы слов, лимит180, пустой текст, пунктуация
  исходного описания и фактический WebSite.
- TypeScript и проверка синтаксиса браузерного теста.
- CI: SEO unitcheck добавлен к существующей сборке. После наполнения
  изолированной базы полный HTTP SEO-check сохраняет `seo-http.json`.
  Он также проверяет единственный WebSite только на главной.
- Существующие21 Chrome-сценарий на трёх размерах дополнены проверками
  WebSite, обоих новых описаний и неизменного видимого условия пакетов.

При подготовке этого коммита CI, просмотр его снимков и публикация ещё
ожидаются. Финальное состояние проверяется по PR и workflow run.
Физический телефон, реальные обращения и региональные позиции здесь
не измеряются. Изменения поисковых кабинетов и настроек GitHub gate в этот
пакет не входят.
