# Галереи праздников

## Общий интерфейс

`frontend/src/components/photo-gallery.tsx` принимает массив `{ url, alt, position }`, заголовок и описание. Используется на `/gallery`, в галереях персонажей через `CharacterGallery` и на подробных страницах услуг, для которых зарегистрированы фотографии. На странице показывает первые четыре фотографии на ПК и первые две при ширине до 700 CSS px. Полный массив остаётся доступен в открытом просмотре.

Кнопка «Все фотографии · N» появляется только при наличии скрытых кадров: больше четырёх на ПК, больше двух на телефоне. Она открывает первый кадр полного просмотра. Нажатие на превью открывает выбранный кадр. После закрытия фокус возвращается к нажатой фотографии или к кнопке всех фото. Автопрокрутки слайдов нет.

Фотографии открываются в native `<dialog>`: стрелки, циклическое перелистывание, миниатюры, счётчик, клавиши ←/→ и Esc, горизонтальный свайп на сенсорном экране. Большой кадр показывается целиком через `object-fit: contain`; миниатюры кадрируются. При открытии блокируется прокрутка страницы; при закрытии фокус возвращается к исходной фотографии. Активная миниатюра остаётся видимой в длинной ленте.

## Добавление фотографий

- **Персонажи:** существующая Django-модель `CharacterPhoto` и API `photos`; указываются alt, порядок и видимость. Миграция для нового просмотра не нужна.
- ID записи `CharacterPhoto` постоянный, `position` отвечает только за порядок. Для перестановки меняем позиции существующих записей, не удаляем и не создаём фотографии заново. При будущей загрузке новых подборок начальный порядок — по имени исходного файла; затем владелец выбирает первые четыре кадра и их последовательность. Текущие согласованные подборки не пересортированы. Для обсуждения можно использовать ID записи или имя исходного файла; номер в счётчике галереи — текущая позиция, а не постоянный идентификатор. Для локальных подборок услуг идентификатором служит имя файла, таблица соответствия пиньяты приведена ниже.
- **Услуги и пакеты:** пока локальные подготовленные изображения в `/public/media/gallery/<slug>/`, регистрация в `frontend/src/lib/offering-gallery.ts`. При появлении необходимости управлять ими через админку можно добавить связь фото с предложением; сейчас дополнительные сущности в базе не создавались.
- Предпочтительны оптимизированные WebP с длинной стороной до 1800 px. Исходники сохраняются отдельно; EXIF не переносится в публичную копию.

### Обработка двух кадров

По запросу владельца из DSC_5389 убран Фиксик: кадр приближен, остатки костюма у левого края удалены. Пиньята и девочка с битой сохранены. В DSC_5482 синий костюм заменён на красный костюм гонщика с клетчатыми полосами и кепкой; без глаз, номера 95, эмблем и символики Макквина. Использован встроенный imagegen, итоговые кадры визуально проверены в галерее. Это обработанные фотографии, а не неизменённые исходники. Замена костюма не является юридической проверкой остальных объектов в кадре.

Оригинальные две публичные копии сохранены в игнорируемой `.local/backups/pinata-originals/` и удалены из `public`; галерея использует новые имена файлов для обновления кеша. Точные промпты — `.local/pinata-edit-prompts.md`.

В RB3009-352 дополнительно выровнен свет встроенным imagegen: смягчены пересветы, улучшена фактура жёлтой пиньяты и белого костюма, скорректирован цвет кожи и контраст. Используется `yellow-pinata-balanced.webp`; исходная публичная копия также сохранена в `.local/backups/pinata-originals/`.

При продолжении приёмки 7 октября владелец подтвердил, что красный костюм гонщика с обработанной фотографии есть у команды и его можно заказать. Вопрос о соответствии образа доступной программе закрыт; факт обработки снимка остаётся указанным выше.
