# Аналитика сайта и формы

Обновлено 8 октября 2026. Счётчик Яндекс Метрики **105020810**, сайт **https://mu56.ru**, часовой пояс Оренбурга (UTC+5). В существующем счётчике созданы 16 JavaScript-целей с точным совпадением идентификатора. Google Analytics не установлен.

## Что измеряем

| Идентификатор | Что произошло | Как использовать |
| --- | --- | --- |
| `form_open` | Открыли форму | Интерес к обращению, страница входа |
| `form_start` | Первое изменение поля или выбор | Доля посетителей, начавших заполнять |
| `form_progress` | Первое взаимодействие с каждым полем | Какие этапы используют, обязательны ли подробности |
| `contact_ready` | Введён допустимый по формату телефон | Дошли до контактных данных |
| `details_open` | Раскрыли необязательные детали | Нужен ли посетителям подробный подбор |
| `program_select` | Выбрали программу | Популярность программ в форме |
| `hero_select` | Выбрали первого или второго героя | Интерес к героям |
| `form_submit` | Прошли нативную проверку и начали отправку | Попытки отправки, повторные попытки |
| `validation_error` | Браузер попросил проверить поле | Какие поля мешают отправить |
| `submit_error` | Ошибка сети, тайм-аут, CSRF или ответ API с ошибкой | Технические потери |
| `lead_success` | API подтвердил сохранение заявки | Главная конверсия сайта |

| `contact_click` | Нажали телефон или ссылку на площадку | Альтернативные способы обращения |
| `catalog_search` | Поиск в каталоге с паузой 800 мс | Частота поиска и отсутствие результатов |
| `catalog_filter` | Выбрали категорию или сортировку | Используют ли навигацию каталога |
| `media_interact` | Открыли/листали галерею, запустили/досмотрели HTML-видео | Интерес к фото и видео |

Обычные просмотры страниц также учитываются, включая переходы внутри Next.js. Успешная заявка и клик на контакт — разные цели: клик не подтверждает звонок, сообщение, бронирование или оплату. События видео относятся к HTML-видео сайта; встроенные внешние плееры этой интеграцией не измеряются.

Локальное дополнение 8 октября: ссылка на карточку площадки в Яндекс Картах
учитывается в `contact_click` с `channel=maps`. Передаётся только название
канала, URL и его параметры в событие не включаются. Другие страницы Яндекса
и похожие сторонние домены не считаются переходом на карту. Цель существующая,
добавлять отдельную цель в кабинете не требуется. TypeScript и проверки
аналитики прошли; получение нового канала Метрикой после публикации ещё
не проверено. Изменение пока не опубликовано.

## Параметры и приватность

Передаются только публичные идентификаторы программы/героя, тип программы, число дополнений, диапазон предварительной цены, название этапа, фиксированный тип ошибки, HTTP-статус, число попыток и время с открытия формы (до 3600 секунд). Поле `schema=v1` обозначает версию контракта. Поиск передаёт число найденных героев, но не поисковую фразу. Фильтр передаёт индекс категории в текущем каталоге; сравнивать индексы можно только при неизменном составе категорий.

Не передаются имя, телефон, адрес, дата/время праздника, пожелания, согласие как документ, идентификатор заявки или сырые тексты ошибок. Событие `contact_ready` означает только соответствие формату телефона, а не проверку существования номера. URL без query/fragment; внешний referrer — только origin, без пути и параметров. Вебвизор, карта кликов и автоматическое отслеживание ссылок в коде выключены; Вебвизор выключен и в настройках счётчика. Форма дополнительно помечена `ym-disable-keys`.

SDK Метрики загружается только после отдельного разрешения аналитики. До выбора и при отказе он не загружается. Выбор хранится в localStorage (`mu56-analytics-v1`); внизу страницы есть «Настройки аналитики» для изменения решения. Отзыв разрешения прекращает работу счётчика и удаляет доступные странице cookies `_ym_*`. Уже полученные Метрикой сведения не удаляются этим действием. Форма работает независимо от разрешения аналитики. На localhost и dev.mu56.ru события отключены.

SDK всё равно получает технические сведения визита, например IP и сведения браузера. «Содержимое формы не записываем» не означает полностью анонимный технический запрос. Нет собственного идентификатора посетителя и связывания данных Метрики с конкретной заявкой в базе.

Подготовлена горизонтальная плашка: текст слева, кнопка «Согласен» справа, без крестика. До согласия аналитика выключена. В «Настройках аналитики» внизу сайта остаётся действие «Отключить аналитику», которое сохраняет отказ и скрывает уведомление на 24 часа. Предыдущие закрытия крестиком также учитываются до истечения 24 часов. На узких экранах текст переносится без обрезки; фиксированные две строки не гарантируются.

## Как анализировать

### Сводка сохранённых заявок без персональных данных

Подготовлена команда `report_leads`. Она только читает базу, не отправляет
сообщения и не меняет заявки. Например, для полного периода 9–15 октября:

```bash
python manage.py report_leads --start 2026-10-09 --end 2026-10-15
```

Обе даты включительны, границы дня считаются по Оренбургу (UTC+5).
JSON содержит число заявок, группировки по текущему статусу и slug основной
программы, состояния уведомлений и число заявок без записи уведомления.
Имена, телефоны, адреса, пожелания и идентификаторы заявок не выгружаются.
Статусы отражают момент выполнения отчёта, а не историческое состояние.
Тестовые заявки включены: надёжного признака теста в базе сейчас нет.
Отмечать известные тесты отдельно; не удалять их автоматически по имени
или телефону. Пустая программа означает «нужно помочь выбрать».

Сводки хранить в `.local/`, а не в публичном Git. У команды нет нового HTTP
endpoint; она доступна только через существующий административный запуск
Django. Локально прошли проверки границ дня, группировки, отсутствия личных
полей и неизменности данных; весь набор leads прошёл 84 теста с одним
пропуском проверки PostgreSQL на SQLite. До нового релиза команда на
сервере недоступна; результат локальных тестов не означает её публикацию.

Открыть [Метрику](https://metrika.yandex.ru/dashboard?id=105020810), выбрать период и счётчик. Использовать «Конверсии» для целей, отчёты по источникам, устройствам и страницам для разрезов, отчёт параметров целей для `field`, `reason`, `program`, `hero`, `seconds`, `attempt` и `price_band`.

1. Основная воронка: визиты → визиты с `form_open` → визиты с `form_start` → визиты с `form_submit` → визиты с `lead_success`. Сравнивать **визиты с целями**, а не сумму срабатываний: один человек может открыть форму и отправить её несколько раз. Отдельные цель-счётчики не доказывают последовательность внутри визита — для строгой последовательности использовать сегмент визитов с соответствующими условиями.
2. Потери до заполнения: визиты с открытием, но без начала. Потери при заполнении: с началом, но без успешной заявки. Отдельно смотреть `validation_error`, `submit_error` и `form_abandon` по последнему полю и времени.
3. Сравнить мобильные и компьютеры, страницы открытия и источники трафика. Обязательно показывать абсолютное число визитов вместе с процентами. Несколько тестовых визитов не основание менять форму.
4. Не ставить телефон, детали, героя и дату обязательными шагами одной линейной воронки: часть полей необязательная, некоторые посетители отправляют короткую заявку. `form_progress` — взаимодействие, а не доказательство заполнения или корректности поля.
5. Сопоставить число реально сохранённых заявок в админке за тот же период. Ожидаемое расхождение: посетитель отказался от аналитики, блокировщик, сеть или закрытие страницы. Заявки из базы — источник истины; уведомление Telegram проверяется отдельно.

`pagehide` отправляется по возможности: браузер может не успеть доставить событие, особенно на телефоне. Возврат через историю может дать `resumed=true` и новое открытие после уже отмеченного ухода. Поэтому `form_abandon` — диагностический сигнал, а не точное количество потерянных клиентов. Отсутствие успешной цели в визите надёжнее использовать как отдельный сегмент, но и оно не исключает сохранение заявки при потере ответа API.

Сначала проверить доставку новых событий, затем анализировать окна **7 и 28 дней** с одинаковыми фильтрами. Период не гарантирует достаточной выборки. Тесты владельца и разработчика помечать отдельно в отчёте/исключать согласованным сегментом; локальная разработка автоматически не учитывается. UTM и сырые referrer-параметры в этой версии не передаются, поэтому детализация рекламных кампаний ограничена.

Для передачи в следующий чат достаточно CSV из отчётов: период, выбранные сегменты, визиты/посетители, визиты с каждой целью, устройства, источники, страницы и параметры целей. Не присылать выгрузку персональных заявок. Сохранённые отчёты должны иметь понятные имена: «Форма — воронка», «Форма — ошибки и уходы», «Каталог и контакты». Пока данные не накоплены, выводы об удобстве формы не делать.

## Проверки и состояние

`node --experimental-transform-types scripts/check_analytics.mjs`: фильтрация личных значений, разрешение/отказ и домен, отсутствие дублей начала/успеха, ошибки и повторные отправки, закрытие/возврат. Проверка добавлена в GitHub Actions. TypeScript и изолированная production-сборка прошли. Цели в интерфейсе Метрики созданы и проверены. Коммит `28f64471f8e45a8806b219d45766e544b10c504f` опубликован на mu56.ru: GitHub run 37691322743 завершился успешно, SHA в `/srv/projects/mu56/releases/current.json` совпадает, главная отвечает HTTP 200. В публичном браузере баннер и форма работают; до выбора script SDK отсутствовал. После разрешения script добавлен, но загрузка из сети компьютера не завершилась (curl: TLS handshake failed), тогда как сервер получил HTTP 200 от официального SDK. Владелец подтвердил проверку с телефона через мобильную сеть. Приём публичных событий подтверждён после теста с телефона: виджет открытия формы показывает Google Android, виджет закрытия без отправки — 1 целевой визит. Виджет успешных заявок также показывает достижение, но агент не создавал реальную заявку и не сверял конкретную запись в базе с этим событием. Настройка «Не учитывать мои визиты» выключена; фильтр оставляет трафик сайта и дополнительных адресов, фильтрация роботов по поведению выключена. Публичный отказ с перезагрузкой также проверен: script SDK отсутствует. Успешные события в изолированной локальной проверке с заглушкой не являются подтверждением получения событий Яндексом.

Изменения: `analytics.ts` (контракт и фильтрация), `form-journey.ts` (состояние одной формы), `site-analytics.tsx` (разрешение, SDK и просмотры), интеграции формы/галереи/каталога. Backend и база не изменены. Изменять идентификаторы целей следует одновременно с настройками Метрики и этим документом.

Официальные источники: [reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal), [параметры целей](https://yandex.ru/support/metrica/ru/data/visit-params-data), [SPA](https://www.yandex.ru/support/metrica/ru/code/counter-spa-setup), [условия Метрики](https://yandex.ru/legal/metrica_termsofuse/ru/).

Мобильная проверка разрешения на ширине 390 px: отказ оставляет SDK незагруженным, настройки позволяют изменить решение, после разрешения заглушка получила init/hit/form_open; попытка отправки пустой формы дала validation_error для телефона и согласия без POST, закрытие — form_abandon, отзыв — destruct. Новых реальных заявок в рамках этой проверки не отправляли.
