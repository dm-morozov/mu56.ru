# Дальнейшая работа

Актуальный поэтапный план от 2 октября 2026 года — [ROADMAP.md](ROADMAP.md). Ниже — детали уже выполненных этапов и подготовленных направлений.

## 1. Скорость изображений — выполнен первый этап

Фото и прозрачные персонажи используют Next.js Image: адаптивные размеры, WebP для поддерживающего браузера, кеш и отложенную загрузку. Главное фото имеет высокий приоритет загрузки. SVG-логотип остаётся исходным. Оригиналы не переписаны и не сжаты.

HTTP-проверка трёх изображений: Человек-паук 384 px — 30 186 байт вместо 19 731 098; Бамблби 750 px — 75 772 вместо 3 981 688; Оптимус 750 px — 27 944 вместо 1 459 221. Это сравнение отдельных вариантов изображений, а не всего сайта или Core Web Vitals. На экранах с высокой плотностью браузер выбирает больший вариант. Проверены сохранение прозрачности и оптимизация фото из Django uploads. Отчёт: image-check.json.

После развёртывания Next.js нужен доступ к backend uploads и дисковый кеш `.next/cache/images`. При первом запросе новый размер генерируется; повторные запросы используют кеш. Медиа и базу нужно резервировать независимо от Git.

## 2. AI-поиск — подготовлен доступ

При включённой индексации OAI-SearchBot разрешены публичные страницы; служебные разделы исключены. Локально сохраняется общий запрет обхода. Остальные поисковые роботы используют общий разрешающий режим после запуска. Доступность в ответах AI ещё не проверена: сайт пока локальный.

Робот поиска OAI-SearchBot и робот обучения GPTBot управляются независимо: [официальная документация OpenAI](https://developers.openai.com/api/docs/bots). В этом этапе политика GPTBot не изменена; отдельное решение по обучению можно принять перед публикацией.

Для Google AI-поиска основой остаются доступные страницы и полезный контент. Google не использует llms.txt для повышения видимости: [официальное руководство Google](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide). Файл llms.txt и скрытые тексты специально для AI сейчас не добавлены.

## 3. Продажи и контент

Готовы отдельные страницы для праздников в детских садах, выпускных и больших мероприятий, общий раздел /holidays и переходы с главной. Существующие предложения сохраняют цены буклета; состав для большой группы согласуется индивидуально. Показывать реальные примеры, понятный выбор числа ведущих и звука, переходы к трансформерам и пакетам. Расширять статьи по вопросам клиентов, а не автоматически копировать чужие материалы.

## 4. Обработка заявок

Реализация уведомлений владельцу готова: очередь в PostgreSQL, обработчик, повторы и состояние в админке. Настройка и команды — docs/TELEGRAM.md. Владелец настроил отдельного бота локально; отправлены проверка связи и тестовая заявка через UI сайта. Telegram подтвердил отправку, в очереди статус sent. Обработчик работает локально; при развёртывании потребуется отдельный сервис с автозапуском. Токен в чат не присылать. Статусы, заметки, рабочие фильтры и история изменений в админке уже реализованы. Клиентский бот и календарь — отдельный этап.

## 5. Подготовка к запуску

Настроить Git и резервные копии, подготовить развёртывание Django/PostgreSQL и Next.js на Selectel, HTTPS, медиа, отдельные dev/prod настройки и восстановление из копии. GitHub хранит код; SSR-фронтенду нужен работающий сервер. Перед публичным запуском завершить текст согласия и проверить контакты, цены и доступность ролей. Действующий mu56.ru до отдельного развёртывания не менять.

## 6. Продвижение и измерение после запуска

Подключить Яндекс Вебмастер, Google Search Console и аналитику. Измерять переходы к программам, успешные заявки и каналы связи, затем качество и стоимость заказов. Проверить внешнее обнаружение страниц, доступ поисковых роботов и скорость на мобильном интернете. Для локального продвижения уточнить существующие карточки бизнеса и актуальность данных. Не обещать топ выдачи по одному техническому чек-листу.
