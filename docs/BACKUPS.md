# Локальная резервная копия и проверка восстановления

Запуск из корня проекта:

```powershell
& .\scripts\dev_postgres.ps1 Load
.\.venv\Scripts\python.exe scripts/backup_local.py
```

Скрипт принимает только отдельный локальный PostgreSQL mu56 на 127.0.0.1:55456. Создаёт новую папку .local/backups с уникальным именем: database.dump, source.zip, media.zip и manifest.json. .local исключена из Git. Копия базы содержит заявки и пользователей админки: хранить её приватно.

Код включает backend, frontend, scripts, docs и корневые Markdown-файлы. Зависимости, сборки, SQLite, .env (кроме шаблонов), кластер PostgreSQL и секреты .local не копируются. Медиа Django идут отдельным архивом; публичные ассеты frontend входят в код. Исходный буклет, исходный тяжёлый архив scraper и старый вложенный репозиторий mu56 не входят: это резервная копия текущего приложения, не всего исходного архива владельца.

После дампа скрипт создаёт новую базу mu56_restore_<случайный суффикс>, восстанавливает схему и данные без перезаписи mu56 и сравнивает число строк каждой публичной таблицы. Zip проверяются чтением и SHA-256 каждого файла; контрольные суммы архивов и таблицы сохраняются в manifest.json. При изменении данных между дампом и сравнениями проверка может не пройти — повторить в период без записи.

Восстановленная база остаётся для осмотра. Приложение и Telegram worker к ней не подключаются; запуск обработчика на копии с очередью недопустим без отдельного решения. Скрипт не удаляет старые копии или базы.

## Полное локальное восстановление 2 октября 2026

- Копия: `.local/backups/20261002T153805Z_8edf66`, база `mu56_restore_32041c1a8c39`.
- 22 таблицы восстановлены; количество строк совпало для каждой таблицы.

- Исходники и медиа распакованы в `.local/restore-check`; создано новое Python-окружение, установлены закреплённые зависимости, фронтенд установлен с frozen lockfile.
- Все 57 Django-тестов, проверка применённых миграций и production build фронтенда прошли в восстановленной папке.
- Django запущен на 8001 с восстановленной базой и `TELEGRAM_ENABLED=false`, Next.js — на 3001 с `BACKEND_ORIGIN=http://127.0.0.1:8001`. В браузере проверена `/animators`: цена, изображения персонажей и обе фотографии галереи загружаются.
- Telegram worker для копии не запускался, заявки из копии не отправлялись. Временные серверы после проверки остановлены. Основное приложение использует прежнюю базу.

Это восстановление в отдельную папку и базу на том же компьютере, с установленными PostgreSQL, Node.js и Python. Оно не заменяет проверку восстановления на новом сервере или внешнюю копию. Локальные параметры подключения использованы отдельно; секреты отсутствуют в архивах приложения.

## Следующие действия

Сохранить вторую защищённую копию на другом носителе: копия на том же диске не защищает от его потери. Место внешнего хранения и расписание согласуются отдельно; облачные загрузки не выполнялись. Секреты восстанавливаются отдельно из безопасного хранилища владельца. Перед production потребуется процедура согласованного копирования базы и медиа во время загрузок, срок хранения и проверка восстановления на отдельном окружении.
