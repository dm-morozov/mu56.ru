# Публичный мобильный baseline — 11 октября 2026

Пункт 31 roadmap. Только измерение опубликованного сайта до выкладки
локального объединённого пакета. Код, фотографии, сервер, CI и общие планы
в этом блоке не менялись. Заявки и уведомления не отправлялись.

## Версия и условия

- SHA опубликованного релиза по переданному основным чатом состоянию:
  `79c4d0e`. Сам SHA не обнаружен в HTTP-заголовках и независимо через сервер
  не проверялся. Признак старого публичного пакета непосредственно в отчёте:
  cover «Винни-Пуха» ещё имеет sizes="(max-width:700px) 100vw, 1100px".
  Локальные новые carouselSizes здесь ещё не измеряются.
- Главная: fetchTime `2026-10-10T21:15:15.288Z`, то есть
  11 октября 00:15:15 Europe/Kiev. Площадка:
  `2026-10-10T21:15:44.863Z`, 11 октября 00:15:44 Europe/Kiev.
- Уже установленный Lighthouse CLI 13.5.0, HeadlessChrome 155.0.0.0,
  Windows. Никакие пакеты или браузеры дополнительно не устанавливались.
- Mobile, экран 412×823, DPR 1,75. Стандартное simulated throttling:
  RTT 150 мс, throughput 1638,4 Kbit/s, CPU slowdown ×4.
  Это модель сети и CPU, не настоящий телефон/оператор.
- Два последовательных запуска, каждый с отдельным временным профилем
  Chrome, стандартный storage reset включён. Серверный кэш не очищался.
  Принятие аналитики не выполнялось; network-requests обоих отчётов содержит
  только mu56.ru. Замер после согласия с работающей Метрикой не проводился.
- Runtime error отсутствует, runWarnings пуст у обоих отчётов.
  benchmarkIndex машины различался: 1682,5 / 3256,5. Фоновую нагрузку
  других задач не контролировали; это дополнительная причина не считать
  одиночные числа устойчивым результатом и не сравнивать страницы напрямую.
- Исходная попытка в песочнице не смогла запустить Chrome; curl там не
  разрешал домен. Успешные отчёты сняты вне сетевой песочницы.

## Что показали измерения

### Главная

LCP-элемент — главное фото Бамблби. Оно найдено в исходном HTML,
имеет eager и fetchpriority=high. Мобильный AVIF передан за 43039 байт
(transfer size вместе с заголовками). Image delivery insight не нашёл
кандидатов экономии; массив items пуст, estimated wasted bytes = 0.

Заметный кандидат дальнейшего анализа — занятость основного потока:
Style & Layout 2061 мс, Script Evaluation 1349 мс. Bootup time выделяет
чанки `0l47w_u94y-jf.js` (около 950 мс scripting) и `0nw9-v24wnahr.js`
(около 347 мс). Это атрибуция Lighthouse, а не доказательство конкретного
компонента или лишнего обработчика. TBT 310 мс подтверждает наличие
блокирующей работы в этом запуске, но не равен INP реальных посетителей.

### «Винни-Пух»

LCP — обложка карусели, eager и доступна в HTML. Вариант w=750&q=75
передан за 44678 байт. Image delivery insight также без кандидатов экономии.
LCP discovery отмечает отсутствие fetchpriority=high, однако оценка
экономии LCP = 0. В наблюдаемой трассе задержка начала загрузки около
12 мс: массовое добавление priority или срочная правка не обоснованы.

Script Evaluation 1302 мс, Style & Layout 1172 мс; TBT 236 мс.
Render-blocking insight перечисляет общий CSS 10675 байт и три небольших
CSS страницы (5775/1842/931 байт). Наличие CSS в этом списке не доказывает,
что его нужно удалять или загружать после первого экрана.

Длительности подэтапов в LCP breakdown относятся к наблюдаемой трассе;
их сумма не обязана совпадать с simulated LCP из таблицы. Не смешиваем
эти два режима в расчёте обещанной экономии.

## Следующая рекомендация

Текущая доставка фотографий достаточна для продолжения согласованного
релиза. Пересжатие, смена формата всего каталога, усиление сервера и изменение
HTML no-store ради балла не назначаются. На площадке результат уже 90+,
а главная близка к этому уровню; 100 не является самостоятельной целью.

После объединённой выкладки повторить замер главной в тех же условиях
2–3 раза, записав новый SHA. Если TBT и работа Style & Layout остаются
заметными, сделать отдельный профиль первого экрана и гидратации,
сопоставить длинные задачи с конкретными компонентами и только затем
предлагать одну измеримую правку. По текущим данным обещать выигрыш от
конкретного рефакторинга нельзя. Для «Винни-Пуха» достаточно сопоставимого
контрольного замера после изменения sizes; мобильный кандидат может
остаться w=750, поэтому экономия в этом viewport не гарантирована.

## Сырые материалы и воспроизведение

Локально, не для публичного Git:

- `.local/performance-baseline-20261011/home.json`
- `.local/performance-baseline-20261011/vinni-puh.json`
- `.local/performance-baseline-20261011/summary.json`
- `.local/performance-baseline-20261011/home-headers.txt`

Команда каждого успешного замера: установленный Lighthouse cli/index.js,
точный URL выше и аргументы
`--only-categories=performance --output=json --output-path=<report.json>`
`--chrome-flags="--headless --disable-gpu" --quiet`.
CHROME_PATH указывает на установленный Google Chrome. Без --preset=desktop,
без обхода проверки сертификата, без отключения очистки storage.

Методика инструмента: https://developer.chrome.com/docs/lighthouse/performance/
Баллы и причины выше взяты из собственных сохранённых JSON, не из документации.
