# Дополнительная оптимизация — 8 октября 2026

## Принятые изменения

- Для единственного небольшого состояния выбора в форме заказа Redux Toolkit и React Redux заменены на `useReducer` и два React context: состояние и dispatch. Внешний API компонентов (`choose`, `close`, `useSelection`, `useAppDispatch`) сохранён. Состояние создаётся отдельно для каждого provider, серверного глобального store нет.
- Удалены две прямые зависимости и 10 пакетов из lock-файла. Передаваемый JavaScript главной страницы в одинаковых локальных измерениях уменьшился с 167 800 до 157 976 байт: минус 9 824 байта (5,9%). Это размер сетевой передачи всех JavaScript-ресурсов, а не исходников.
- Мобильный HeroPicker теперь сначала читает геометрию и рассчитывает допустимую прокрутку, затем меняет scrollTop и CSS. Устранена последовательность записи прокрутки и следующего за ней чтения размеров. Она возникала при открытом списке, а не при первоначальной загрузке главной.
- Проверка переходов состояния формы добавлена в GitHub Actions.

Изображения, тексты, цены и стили не менялись.

## Сравнение вариантов

Production-сборки проверялись по три раза подряд на одном адресе `127.0.0.1:3163`, с одинаковым снимком каталога на отдельном GET-only API `127.0.0.1:8163`. Lighthouse: mobile, штатное замедление, одинаковый Chrome. Серии выполнялись последовательно. Это локальный сравнительный эксперимент, а не новый PageSpeed-отчёт публичного сайта.

| Вариант | Баллы трёх прогонов | Медиана LCP | Медиана TBT |
| --- | --- | --- | --- |
| Исходный | 90 / 89 / 88 | 3 640 мс | 53 мс |
| React reducer | 90 / 89 / 91 | 3 432 мс | 70,5 мс |
| React reducer + встроенный критический CSS | 88 / 87 / 88 | 3 715 мс | 69,5 мс |

Выигрыш reducer по размеру передачи подтверждён. LCP в этой серии лучше, но разброс TBT не позволяет утверждать устойчивое ускорение обработки JavaScript или гарантировать 100 баллов. Итоговая версия дополнительно содержит перестановку операций HeroPicker; на начальной загрузке этот эффект не выполняется.

## Отклонённые эксперименты и ограничения

Критический CSS (~16,6 КБ исходного текста) встраивался в HTML, полный CSS загружался после него. Такой вариант увеличил gzip HTML примерно до 43,9 КБ и ухудшил медиану LCP относительно reducer на 283 мс. Он оставлен только в локальных артефактах эксперимента; основной layout, CSS и загрузка стилей не изменены.

Указанные PageSpeed полифилы и часть неиспользуемого JavaScript находятся в runtime Next/React, а не в отдельном ненужном собственном скрипте. Удаление произвольных частей runtime не выполнялось. Принудительная компоновка исходной загрузки в trace имеет источник `[unattributed]`; конкретная причина в собственном коде не установлена, поэтому исправление HeroPicker не выдаётся за устранение этих 68 мс публичного отчёта.
