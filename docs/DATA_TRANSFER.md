# Перенос каталога на первый сервер

`export_catalog` переносит только восемь моделей каталога: персонажей, предложения, тарифы, этапы пакетов, контакты, отзывы, статьи и фотографии. Сохраняет скрытые записи, черновики и даты публикации. Заявки, пользователи, сессии, внутренние заметки и очередь Telegram не включаются. Непривязанные к каталогу файлы media не переносятся; исходные файлы не удаляются.

Фото/видео из `frontend/public` идут с релизом через Git, не этим пакетом. Проверить их наличие в будущем удалённом репозитории отдельно. Пакет передавать приватно: в нём рабочие черновики и исходники фото.

## Экспорт на Windows

Во время экспорта не менять каталог и фотографии. База читается из одного снимка REPEATABLE READ; файлы проверяются по SHA-256, но снимок базы не замораживает файловую систему.

```powershell
& .\scripts\dev_postgres.ps1 Load
.\.venv\Scripts\python.exe backend/manage.py export_catalog .local/catalog-release-01
```

Папка должна быть новой. Готовый пакет содержит `catalog.json`, `media.zip`, `manifest.json`. Без manifest экспорт не завершён. Использовать ту же версию моделей и миграций. Контрольные суммы обнаруживают повреждение, но не подтверждают отправителя — принимать только свой пакет.

## Импорт на Linux

Подготовить новую базу, применить миграции. До импорта не запускать seed-команды и не создавать владельца админки. Передать пакет в `/srv/mu56/import/catalog-release-01`, дать пользователю `mu56` доступ на чтение и закрыть папку для остальных пользователей. Путь вне Nginx. Backend/frontend/worker ещё не запускаются.

```bash
sh /srv/mu56/current/deploy/manage.sh migrate
sh /srv/mu56/current/deploy/manage.sh import_catalog /srv/mu56/import/catalog-release-01 --replace-migration-defaults
sh /srv/mu56/current/deploy/manage.sh createsuperuser
```

Миграция 0002 создаёт одну начальную запись Деда Мороза и Снегурочки даже в новой базе. Флаг разрешает заменить только эту единственную неизменённую запись, если других записей каталога, заявок и пользователей нет. Изменённая запись или любой другой непустой каталог отклоняются. Произвольная очистка базы не предусмотрена.

Перед записью проверяются модели/поля, уникальность ID, количества, ссылки на фото и контрольные суммы. Импорт восстанавливает связи и последовательности ID; отличающиеся существующие фото не перезаписывает. База записывается транзакцией. Файловая система не транзакционная: при ошибке записи могут остаться новые непривязанные файлы. После ошибки не включать службы, устранить причину и повторить проверку.
