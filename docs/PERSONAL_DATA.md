# Заявка и согласие на обработку данных

6 октября 2026: локальная доработка, без публикации на действующем сайте.

- `/consent` — самостоятельный текст согласия; `/privacy` — политика.
- В форме одна обязательная, изначально пустая отметка согласия для обработки заявки. Политика доступна отдельной ссылкой; рекламного согласия нет.
- `frontend/src/lib/lead-consent.json` — общий источник текста и версии для frontend и Django. Этот файл должен присутствовать в release рядом с обоими приложениями, даже при отдельной сборке backend.
- JSON заявки содержит `consent_version`. Django отклоняет отсутствующую или устаревшую версию до создания заявки и Telegram-уведомления. Сохраняются время и проверенная версия согласия. Старые записи согласия не переписываются.
- При изменении условий или текста нужно менять версию и сохранять прежнюю редакцию в истории исходников. Frontend и backend выпускаются совместно.

## Проверка перед запуском — 7 октября 2026

- По статье 22 уведомление требуется до начала автоматизированной обработки, если нет применимого исключения. Владелец подтвердил 7 октября: уведомление ещё не подавалось. Работа одного физического лица сама по себе не освобождает от требований для клиентских заявок. Следующий шаг — подготовить достоверные сведения для уведомления и подать его; дату начала обработки не заменять будущей датой запуска сайта.
- По статье 12 уведомление о трансграничной передаче подаётся отдельно. Для текущих полных уведомлений Telegram нужно установить получателя, страны обработки и применимый порядок до публичного запуска; IP API не подтверждает расположение всех данных. Одного текста согласия недостаточно.
- В политике явно указано: даже при выборе звонка сведения формы поступают владельцу через Telegram. Версия согласия v2 не менялась: эта передача уже описана в согласии; уточнена только политика.
- Возможный вариант уменьшения передачи: уведомлять о новой заявке без имени, телефона и пожеланий, а детали читать в защищённой админке. Это предложение, а не внедрённое изменение; даже ссылку/идентификатор нужно оценить на возможность идентификации.
- Удаление: при достижении цели или отзыве проверить основания дальнейшего хранения; при отсутствии оснований применить сроки статьи 21, включая общее правило до 30 дней и предусмотренные законом исключения. Проверять базу, сообщения Telegram, выгрузки, журналы и резервные копии. Хранение архивов 90 дней не является самостоятельным основанием хранения уже подлежащих уничтожению данных. После восстановления копии повторно применять выполненные удаления до запуска уведомлений.
- До запуска осталось подтвердить статус уведомления, канал письменных обращений и практический порядок удаления. Автоматическое удаление и подача уведомлений не выполнены. Основной домен не переключался.

Источник проверки: [152-ФЗ на сайте Минтруда, статьи 12, 21 и 22](https://mintrud.gov.ru/docs/laws/130), просмотрено 7 октября 2026; опубликованная редакция включает изменения по 24 июня 2025. [Форма уведомления РКН](https://pd.rkn.gov.ru/operators-registry/notification/form/) при автоматическом просмотре не загрузилась; заполнение не выполнялось.

Проверки: production build Next.js с TypeScript; 102 теста catalog/leads, включая отказ для старой/отсутствующей версии согласия. На отдельной свежей локальной сборке (порт 3105) обе страницы возвращают 200, документы и ссылки присутствуют в HTML. Существующий preview на 3000 для новой страницы возвращал 404, поэтому для проверки использована отдельная сборка. Внешних сообщений и изменений production при проверках не выполнялось.
