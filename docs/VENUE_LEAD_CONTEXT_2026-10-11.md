# Интерес к площадке в заявке — 11 октября 2026

Локальная backend-реализация пункта 3 `BOOKING_CONTEXT_REVIEW_2026-10-11.md`.
Frontend пока не интегрирован в рамках этого участка; production не изменён.

## Контракт для основного чата

В существующий JSON POST `/api/v1/leads/` добавить необязательный ключ:

```json
{"venue": "vinni-puh"}
```

Это дополнение к прежним полям заявки, не самостоятельный полный payload.
`venue` принимает `vinni-puh` или пустую строку; отсутствие поля совместимо со
старыми клиентами. `null`, неизвестный slug, объект вместо slug и произвольное
поле `venue_name` отвергаются валидацией. Frontend должен сохранить интерес
при смене программы внутри обращения; выбор площадки не подтверждает бронь.

## Хранение и отображение

`location` остаётся свободным местом, указанным клиентом; автоматически его
не перезаписываем. Новая таблица или колонка не нужны: сервер сохраняет в
существующем `selection_snapshot` объект:

```json
{"venue": {"slug": "vinni-puh", "name": "Винни-Пух", "status": "interest"}}
```

Название подставляется из серверного whitelist `VENUE_CHOICES`, а не из
клиентского текста. Читатели в админке и форматировании уведомления также
разрешают название по whitelist, игнорируя произвольное имя из снимка.
При пустом/отсутствующем venue ключ в снимок не добавляется.

В первоначальном составе заявки в админке и тексте будущего уведомления:

> Интерес к площадке: Винни-Пух — доступность и условия согласуем; бронь не подтверждена.

Статус заявки остаётся `new`, признак согласования менеджером сохраняется;
цены, состав программ и правила очереди не менялись. Адреса и партнёрские
ссылки не добавлялись. Миграция не требуется.
