# Локальный «Мир Улыбок» в Docker Desktop

Подготовлено и запущено 9 октября 2026. Проект Docker Desktop: **mu56-local**.

- Сайт: http://127.0.0.1:3000/
- Админка и прямой backend: http://127.0.0.1:8001/admin/
- PostgreSQL доступен только внутри сети Docker, публичный порт не открывается.

Три сервиса: frontend (Next.js dev), backend (Django runserver), database
(PostgreSQL 18). Отдельный Nginx для разработки не нужен: Next проксирует
API и uploads к backend. Режим разработки не заменяет production-сборку
и проверку готового релиза перед публикацией.

## Ежедневная работа

Открыть Docker Desktop и дождаться готовности движка. У ранее работающих
контейнеров restart policy `unless-stopped`: они возвращаются после запуска
Docker. Если остановить проект вручную, он останется остановленным даже
после перезапуска Docker. Тогда запустить mu56-local в Docker Desktop или:

```powershell
cd C:\GitHub\mu56.ru
.\scripts\dev_docker.ps1 Start
.\scripts\dev_docker.ps1 Status
```

Stop — останавливает только этот проект, Logs — выводит последние журналы.
Скрипт не меняет настройку автозапуска самого Docker Desktop при входе в Windows:
работа сайта начинается после запуска движка Docker.

Исходники frontend и backend подключены из рабочей папки. Next использует
webpack и polling файлового наблюдателя для Windows/Docker Desktop; изменения
подхватываются автоматически, иногда с задержкой несколько секунд.
Django перезапускает процесс разработки после изменений Python.
При новых миграциях выполнить:

```powershell
docker compose --env-file .local/docker-dev/compose.env -f deploy/local/compose.yml exec backend python manage.py migrate
```

Фотографии в frontend/public и backend/media берутся из текущей рабочей папки.
Они не копируются на production при локальных правках. Публикация согласованных
изменений остаётся отдельным штатным выпуском в конце работы.

Linux node_modules и .next — отдельные Docker volumes, Windows-зависимости
не используются внутри Linux. Frontend сверяет зависимости с pnpm-lock.yaml
при запуске. При изменении backend/requirements.txt повторить Start для сборки.

## Данные и безопасность

Первый запуск сохранил дамп старой локальной базы в
`.local/docker-dev/windows-local-20261009-124914.dump` (125015 bytes) и
восстановил её без смены владельцев в новый volume `mu56-local_database`.
Старый PostgreSQL Windows на 55456 не удалён и не переключён.
После переноса это **две независимые базы**: изменение каталога в старом
Windows backend не появляется автоматически в Docker и наоборот.
Для текущей разработки используйте Docker backend на 8001 и его админку.
Учётные записи и пароли админки перенесены из локальной базы.
С production база автоматически не синхронизируется.

Случайный пароль Docker PostgreSQL находится только в игнорируемом
`.local/docker-dev/compose.env`. Конфигурация Compose не содержит настоящих
паролей или Telegram-токенов. Локальный .env.local фронтенда внутри контейнера
перекрыт публичным development-шаблоном, чтобы не использовать production URL.
Каталог ai-context и локальные секреты не включаются в образы.

Telegram отключён явно, worker отсутствует. Локальные заявки сохраняются
только локально; не запускайте обработчик очереди со старой локальной
конфигурацией без отдельного решения о доставке. Индексация выключена,
robots запрещает обход. Порты сайта и админки привязаны к 127.0.0.1.

Не выполнять `down -v` и не удалять volume базы для обычного перезапуска.
Start импортирует старую базу только при полностью пустом public schema.
Если первый restore завершится ошибкой и останется частичный импорт,
скрипт не исправляет его автоматически: сохранить дамп и диагностировать.

## Приёмка объединённого пакета, 9 октября

В текущем Next.js dev необходимо явно разрешить loopback origins при запуске
на 0.0.0.0 внутри Docker. В compose и frontend.env.example добавлены только
localhost и 127.0.0.1; next.config.ts уже читает NEXT_DEV_ALLOWED_ORIGINS.
Публичные origins и доступ из локальной сети не добавлялись, bind портов прежний.
До исправления журнал показывал blocked cross-origin dev resource, а после
перезапуска при обновлении старой вкладки был временный HMR router initialization
error. После завершения загрузки форма и галерея работают.

Новогодняя кнопка 20:00 выбирает eve-20; 31 декабря 2026, 20:00 даёт 8000 ₽.
Галерея открывается, следующая фотография меняет 1/2 на 2/2, закрытие работает.
В браузере подтверждены реальные ширины 360/390 px: статьи, Бамблби и выпускной
без горизонтального переполнения; форма на 390 px помещается в ширину экрана.
Экранная клавиатура и свайп настоящего телефона в этом проходе не проверялись.
Мобильный скриншот прервался тайм-аутом и доказательством приёмки не считается.
Локальная проверка с SITE_URL=http://127.0.0.1:3000 не должна сравнивать canonical
с production origin. Для неё использована временная копия SEO-проверки в .local;
production-конфигурация и основной проверочный скрипт не изменены.

Политика перезапуска:
[Docker restart policies](https://docs.docker.com/engine/containers/start-containers-automatically/).
