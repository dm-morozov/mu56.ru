# Небольшая оптимизация главной — 8 октября 2026

Работа выполнена локально. Production не менялся. Другие незавершённые
изменения в рабочем дереве сохранены.

## Изменение

- Для главного фото с Бамблби подготовлены AVIF шириной 750, 1080 и 1437 px
  из исходного PNG, quality 55, effort 6. Исходник сохранён.
- `HomeHeroImage` использует `<picture>` с AVIF и прежним Next Image/WebP
  как резервом. Высокий приоритет, eager и текст alt сохранены.
- Размер 750 px: WebP quality 75 — 82966 байт, AVIF — 59085 байт,
  сокращение 28.8%. AVIF 1080/1437 px: 98625/141752 байт.
- Desktop `sizes` соответствует двум колонкам и пределу контейнера 1240 px.
  На телефоне сохранён запас пикселей для высокого кадрирования object-fit:cover.
- Статические импорты дают версионные адреса `/_next/static/media/`.
  Формат подготовлен до сборки; при первом посещении сервер его не кодирует.
- Генератор: `node scripts/optimize_home_hero.cjs` после установки frontend
  dependencies. Дополнительных зависимостей не добавлено.

## Проверка

Production build и встроенная проверка TypeScript прошли в отдельной копии
`.local/performance-20261008/frontend`. Turbopack предупреждает, что не умеет
сам оптимизировать AVIF: это ожидаемо, используются уже подготовленные файлы.

Фотография сравнена визуально; лица, цвета, детали костюма сохранены.
Браузерная проверка на 360, 412, 768 и 1440 CSS px: изображения загружаются,
горизонтального переполнения нет. При удалении AVIF source работает WebP.
В AVIF-режиме второй запрос к WebP для главного фото не обнаружен.
Дополнительно проверен телефон 412 px с DPR 2: выбран AVIF 1080 px,
ответ 200, image/avif, Cache-Control public,max-age=31536000,immutable.
Финальный кадр сохранён и визуально проверен. Дополнительный проход desktop
DPR 2 завершился таймаутом навигации; этот размер с DPR 2 не подтверждён.
Desktop 1440 px с DPR 1 проверен успешно в основном проходе.

Три последовательных локальных mobile Lighthouse до/после, одинаковый
каталог и тестовый frontend на 3158; аналитика отключена в обоих случаях:

Последующая правка только адресов AVIF на статические импорты прошла сборку

Публичный сайт и реальные полевые Core Web Vitals в этом проходе не проверялись.

## Почему оставлена таблица стилей

Блокирующий CSS около 19 КБ передаваемых данных. Фото уже обнаруживается в
начальном HTML и имеет высокий приоритет; в исходном локальном отчёте
задержка отрисовки около 1.14 с существенно больше скачивания самого фото.
Разделение общего CSS и внедрение critical CSS потребуют более широкого
рефакторинга и отдельной проверки всех страниц. В пределах согласованной
небольшой оптимизации такие изменения не вносились. Полифилы и почти
нулевые смещения также не менялись ради удаления предупреждений.
