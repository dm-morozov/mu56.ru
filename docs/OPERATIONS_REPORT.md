# Приватная сводка заявок и состояния очереди

Helper `scripts/report_site_operations.ps1` использует существующий SSH-ключ
`.ssh/id_ed25519_selectel_vds`, строгую проверку известного ключа сервера
161.104.32.37 и две существующие Django-команды. Пароли не запрашиваются.
Ключ должен быть доступен OpenSSH; для ключа с passphrase нужен настроенный
ssh-agent. Скрипт не создаёт ключи и не добавляет сервер в known_hosts.

Из корня репозитория:

```powershell
.\scripts\report_site_operations.ps1 -Start 2026-10-09 -End 2026-10-15
```

Start и End обязательны, ISO `YYYY-MM-DD`, обе даты включительны. Период заявок
считается по Оренбургу (Asia/Yekaterinburg, UTC+5). Будущий или незавершённый
период не означает полный интервал: для исходного среза 9–15 октября запускать
после окончания 15 октября по Оренбургу. Статусы отражают момент сбора.

Результат — один UTF-8 JSON в игнорируемом `.local/operations-reports/`.
На экран выводится только путь и при необходимости предупреждение о очереди.
Отчёт не включать в публичный Git. Повторный запуск создаёт новый файл,
не перезаписывает старую сводку. SSH-ключ читается клиентом, его содержимое
не копируется в отчёт; можно указать другой существующий ключ через IdentityFile.

Содержимое:

- `leads`: агрегаты report_leads за период: число сохранённых заявок,
  группировки по текущему статусу и публичному slug программы, состояния
  уведомлений этих заявок. Тестовые заявки включены.
- `telegram_current`: telegram_status **для всей текущей очереди**, не
  только выбранных дней; configured, счётчики, просроченные/зависшие состояния,
  healthy. Это не запрос к Telegram и не проверка работоспособности worker.
- `collected_at_utc`: момент получения сводки. Для сравнения отчётов фиксировать
  период, часовые пояса и дату сбора.

Скрипт не запускает worker, не отправляет сообщения, не меняет заявки/БД,
контейнеры, конфигурацию, Git или production. `docker compose exec` только
исполняет команды чтения в уже работающих backend/worker; `up` не вызывается.

При SSH/командной ошибке, неверном JSON, периоде или неожиданной схеме скрипт
завершается ошибкой; новый финальный файл не создаётся. Raw stderr и JSON
ошибки не печатаются. Валидная сводка с healthy=false сохраняется и даёт
предупреждение: плохое состояние очереди — результат проверки, а не ошибка
получения отчёта. Личные поля и неизвестные поля отвергаются, свободные
серверные notes/scope заменяются фиксированным текстом. Если схема команд
изменится, сначала обновить проверки helper, не отключать валидацию.

## Локальная проверка без сервера

```powershell
pwsh -NoProfile -File .\scripts\check_operations_report.ps1
```

Тест подменяет ssh функцией, использует фиктивные агрегаты и временный файл,
не обращается к production. Проверяет строгий host checking, команды,
дату/инъекцию, SSH-код выхода, JSON/схему, личные значения, отказ второй
команды и отсутствие ложного файла при отказе. Фиктивный успешный результат
не является подтверждением production-доступа или состояния реальных заявок.
После теста удаляются только точные файлы, созданные тестом.
