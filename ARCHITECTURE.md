# Техническая основа «Мира Улыбок»

Рабочее решение от 30 сентября 2026, обновлено 1 октября. Готовы Django-каталог, админка, публичный API и сохранение заявок; PostgreSQL проверен локально. Фронтенд и production-сервер ещё не созданы. Владелец подтвердил Django, React, TypeScript, Redux Toolkit и разрешил выбрать размещение и порядок разработки.

## Что за что отвечает

| Часть | Назначение |
| --- | --- |
| Django + Django REST Framework | Каталог, цены, доступность, статьи, заявки, публичный API |
| Django Admin | Редактирование содержания владельцем без изменения кода |
| PostgreSQL | Единый источник данных о предложениях и заявках |
| React + TypeScript на Next.js | Страницы с отдельными URL, готовым HTML и интерактивностью |
| Redux Toolkit | Общий выбор программы, персонажа и дополнений между страницами |
| Selectel | Работающие приложения и база данных |
| GitHub | Закрытый репозиторий исходников обоих приложений |
| Beget | Регистрация домена mu56.ru; DNS направляется на новый сервер при запуске |

Один репозиторий: `backend/`, `frontend/`, `docs/`. Изображения для публикации отделить от тяжёлых исходников и внутренних документов. Версии зависимостей выбрать и закрепить при начале реализации.

## Страницы и обновление данных

Каталоги, программы, персонажи, пакеты, дополнения, Новый год и статьи имеют собственные адреса. Next.js отдаёт основной текст, цены и ссылки в HTML; React обеспечивает переходы и интерактивность. Серверный и предварительный рендеринг помогают доступности содержания для поисковых роботов: [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Данные приходят из Django. Публичные страницы кешируются с явным обновлением после изменения содержания. При реализации проверить, что новая цена появляется на карточке, в каталоге и в HTML без ручной пересборки всего сайта. При недоступности источника не подменять неизвестную актуальность цены обещанием подтверждённой стоимости.

Время публикации статьи проверяется сервером. Черновики и будущие статьи отсутствуют в публичном API, подборках, sitemap и по прямому URL. Обновление кеша при публикации — часть реализации, которую нужно проверить.

Сайт и API доступны на одном домене: страницы обслуживает Next.js, `/api/` и `/admin/` — Django через обратный прокси. Админка требует авторизации; публичный API не отдаёт ставки команды, служебные заметки и контакты клиентов. Конкретный механизм авторизации и обновления кеша определить при реализации.

GitHub Pages не выбран: правила ограничивают бесплатное размещение онлайн-бизнеса, а статический экспорт Next.js требует сборки для обновления страниц и имеет ограничения серверных функций. Источники: [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), [Next.js static exports](https://nextjs.org/docs/app/guides/static-exports).

## Модель содержания

- Персонаж: имя, описание игр, фото, рекомендации по возрасту, доступность с согласованием.
- Программа: состав, продолжительность, тариф, требования пространства, доступные персонажи.
- Пакет: фиксированные компоненты, общая длительность, базовая цена и время работы исполнителей.
- Дополнение: отдельный тариф и исполнитель, длительность и совместимость; может идти параллельно программе.
- Статья: содержание, SEO-поля, статус, дата публикации, связанные предложения.
- Заявка: контакт клиента, дата и место, основной выбор, дополнения, статус обработки.

Цена и доступность имеют единственный источник в Django. Цены буклета — основа начального наполнения. Доплаты второго аниматора хранить как фиксированные значения из буклета; округление вверх подтверждено владельцем. В трансформерах за 6200 ₽ два исполнителя уже включены. Продолжительность пакета не равна сумме времени всех параллельных услуг.

Первый релиз не требует клиентского кабинета, оплаты онлайн, автоматической брони или CRM команды. Каналы общения: телефон +7 903 392-22-29, Telegram и MAX; почта исключена как канал общения с клиентами. Сохранение заявки проверено; получатель будущих уведомлений — Дмитрий в Telegram. Бот пока не подключён, доставка не выполняется и не подтверждена. Непроверенная ссылка MAX не публикуется API до отметки владельца.

Дальнейшие планы владельца: бот в Telegram/MAX, уточняющие вопросы клиенту и внесение согласованного праздника в Google Calendar. До реализации проверить официальные API, правила первого сообщения и идентификацию клиента: возможность написать человеку по одному номеру телефона не считать подтверждённой. Заказ сначала сохраняется в собственной базе; интеграции проектировать отдельно. В первый релиз эти функции не входят.

Последнее уточнение владельца: Next.js допустим ради удобства SEO, подробное объяснение отложено до фронтенда. Сам фреймворк не гарантирует преимущество в выдаче; цель — доступный HTML, корректные страницы и полезное содержание. Последним сообщением разрешено начать реализацию; Django-каталог и первая версия самостоятельного дизайна на Next.js реализованы; форма подключена к API. Текущее состояние и проверки — в `docs/STATUS.md`.

## Порядок работы

1. Завершить текстовую структуру и таблицы условий; подтверждённые ответы не переставлять в брифе.
2. Создать модели Django и админку, наполнить проверенными предложениями и ценами.
3. Реализовать публичный API и обработку заявок.
4. Собрать страницы Next.js, затем разработать самостоятельный дизайн и адаптивную версию.
5. Проверить содержание, формы, обновления цен, публикацию статей, скорость и индексацию.
6. Выбрать ресурсы Selectel, настроить запуск, резервные копии и перенос домена.

Жёсткого срока нет. Размер и цена сервера выбираются перед покупкой. Текущая новогодняя страница mu56.ru остаётся рабочей до готовности замены; при запуске главная станет круглогодичной, Новый год получит отдельный раздел. Контакты старой страницы требуют подтверждения перед переносом. Технологический стек сам по себе не гарантирует поисковый топ.
